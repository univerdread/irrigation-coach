# Decisions

Scaffolding decisions made on 3 October 2026, with the reason and what would reverse each one. The idea doc ([idea.md](idea.md)) stays the source of truth for *what*; this file records *how*.

| # | Decision | Why | Reversible by |
|---|---|---|---|
| D1 | **Engine in TypeScript, app as a React + Vite PWA** (offline via service worker, wrappable as an Android APK with Capacitor). | The phone stack is still an open question. TS runs in a PWA, React Native, Capacitor and Electron; a PWA demos on any phone with no install friction. | If the model teammate's stack is native (Kotlin/Flutter): port `engine/` (~600 lines) and run the same `contracts/fixtures/golden/*.json`, or embed the PWA in a WebView. |
| D2 | **Contracts are language-neutral JSON Schema + JSON fixtures** in `contracts/`. Golden tests live there, not in TS. | App, engine, log and model must plug together later (idea doc: "write the data contract"). Any port proves itself against the same fixtures. | — |
| D3 | **snake_case at every boundary** (engine I/O, log, AI requests). | The explainer receives the plan *as JSON*; one spelling everywhere avoids mapping bugs. | — |
| D4 | **Flow stored in L/min**, normalised at input from bucket test, L/h or m³/h. 1 mm over 1 m² = 1 L. | Build addendum. | — |
| D5 | **Deficit source is pluggable** (`DeficitSource`): `fixture` (golden tests) and `fao56-hargreaves-climatology` (app). Plan output records which one was used. | Build addendum: "pluggable source … behind one interface". Recording it makes logged plans recomputable. | Add a source (sensor colours, calibrated photo) without touching the planner. |
| D6 | **Hargreaves uses Ra in mm/day** (Ra × 0.408). | FAO-56 eq. 52 expects mm/day; the idea doc's formula leaves it implicit, which would be a 2.45× error. Verified against FAO-56 Example 8 (Ra = 32.2 MJ m⁻² d⁻¹ at 20°S, 3 Sept). | — |
| D7 | **Ks (water stress) is evaluated after the day's water inputs.** | Irrigation happens in the morning; a plot refilled today shouldn't be treated as stressed today. With this, the 30-day simulation reproduces the worked example exactly (225 m³ vs 500 m³). | Switch to start-of-day Ks if local guidance prefers. |
| D8 | **Trigger = p × AWC × Zr, with p from FAO-56 Table 22, not adjusted for ETc.** | Keeps the worked example at 30 mm. FAO-56's adjustment `p + 0.04(5 − ETc)` would give 27.75 mm at 5.75 mm/day. | One line in `plan.ts`; decide with an agronomist. |
| D9 | **Default root depth = FAO-56 Table 22 minimum**; the worked example's 0.6 m is a plot-level override. | Conservative for shallow smallholder soils; keeps sourced vs illustrative values separate. | — |
| D10 | **Effective rain default: 80% of reported rain, showers under 1 mm ignored, capped at the deficit.** Missing rain = unknown → pause. | Placeholder (CROPWAT fixed-percentage shape; FAO-56's "< 0.2 ETo is evaporated"). Golden fixtures set fraction 1 so "effective rain" means what the doc says. | Validate locally; it's a config object. |
| D11 | **Pause rule asks one question in a fixed order:** area → flow → method → crop/stage → soil → deficit → rain. | Build addendum: "show no minutes and ask one question". Onboarding order. | — |
| D12 | **A soil check contradicts only when it disagrees with the decision**: "wet" while due, or "dry" while not due. "ok" never contradicts. Two consecutive disagreements → extension officer. | Decision-relevant, and needs no invented band thresholds. A handful of soil is noisy (idea doc). | Tighten once the photo model's error is measured. |
| D13 | **Guardrails are messages, never numbers.** Slope ≥ 8% with furrows, clay ≥ 40%: demo thresholds. | Build addendum: mulch/fertilizer/salinity stay out of the numeric recommendation. | — |
| D14 | **Display rounding only in the UI:** minutes to the nearest 5 (never 0 when pumping is due), litres to 10 L, depths to whole mm. | Engine stays exact. Rounding to 5 minutes also means the voice bank needs only 11 minute clips. | — |
| D15 | **"Several crops per plot" = several plots (beds) sharing one pump.** | Smallest model that gives each crop its own Kc and fits the cap allocator. | — |
| D16 | **Kale (sukuma wiki) uses cabbage parameters**, flagged in the UI. **Stage lengths are placeholders**: FAO-56 Table 11 has no Kenyan rows. | Kale is central to Kenyan smallholder plots and missing from FAO-56. | Replace with KALRO/county values. |
| D17 | **Area pack: EPSG:4326 grid, uint8 layers in base64 JSON.** Root zone = thickness-weighted 0–20 and 20–50 cm. SDs combined conservatively. | Simple to decode offline in any language. | Binary sidecar files when packs grow. |
| D18 | **Area-pack size: the idea doc's "a few MB per sub-county" holds only at ~90 m.** At 30 m, Loitokitok (~6,000 km²) is ~7 M cells/layer, ~40 MB raw. | Measured from the grid maths. | Demo window at 30 m (≈1 MB); whole sub-county at `--cell-deg 0.0008`. |
| D19 | **Proposed demo area: Kimana, Loitokitok sub-county (Kajiado South).** Semi-arid, irrigated tomato/onion along the Kimana/Rombo systems, ties to the doc's Kajiado KAMIS story. | Needs team agreement (idea doc checklist). Alternatives: Kibwezi (Makueni), Mwala (Machakos). | Change `--bbox` and `app/src/demo/area.ts`. |
| D20 | **AI boundary = `app/src/ai/registry.ts`.** Nothing registered → templates. Mock classifier always says `mocked: true`. | Build addendum AI rules. App always works without a model. | — |
| D21 | **Number guard rejects any digit not in the plan's display numbers and any spelled-out number word (EN/SW).** Templates must pass the same guard. | Digits are checkable; "four"/"nne" aren't. Safe failure = template. The guard caught our own "one question first" string. | — |
| D22 | **Log in localStorage for now** (`irrigation-coach/log/v1`), each entry = input + plan + engine version + deficit source. | Enough for "save and reopen a log". IndexedDB once photos are stored. | — |
| D23 | **Dev ports 4640 (dev) / 4641 (preview).** | 4630 is taken by another local project. | — |
